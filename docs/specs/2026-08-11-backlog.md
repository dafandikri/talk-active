These are defects in the **shipping** build. They pay off whether or not the migration lands.

| ID | Task | Size | Owner | Done when |
|---|---|---|---|---|
All four were verified against the code on 2026-08-12, and one earlier claim was **withdrawn** —
see the note below the table.

| ID | Task | Size | Owner | Done when |
|---|---|---|---|---|
| **P0-1** | **The failover chain is invisible to the client.** Per-attempt timeout is 12s and the total chain budget 22s (`src/semantic.mjs:85-86`), but the client aborts at 15s (`src/app.mjs:603`) and discards anything not `mode === 'semantic'` (`:613`). So vendor 1 failing slowly (12s) plus vendor 2 succeeding (any duration) **always exceeds the client's patience** — the multi-vendor chain can only ever deliver from vendor 1. Raise the client timeout above the server's total budget. | S | Backend | With vendor 1 stubbed to time out, a vendor-2 success still renders as semantic. Add a test asserting `clientTimeout > DEFAULT_TOTAL_BUDGET_MS`. |
| **P0-2** | **Grounding false negatives** — `spanIsGrounded` (`src/semantic.mjs:165-169`) does `.trim().toLowerCase()` then `includes()`, with no whitespace or punctuation normalisation. A quote spanning a line break, or one where the model normalised curly quotes or dashes, is discarded **even though it is correct** — silently costing a valid verdict. Normalise both sides before comparing; map back to original offsets for display. | M | Backend | Fixture tests: newline-spanning span, curly quotes, en/em dash, doubled spaces all ground. |
| **P0-3** | **Per-criterion `engine` provenance (INV-2/INV-4).** When a span fails grounding, `:193` correctly drops that verdict back to the deterministic criterion — but the response is still badged `mode: 'semantic'` overall. A result can therefore claim "semantic" while individual criteria were cue-matched, and nothing on screen distinguishes them. Record `engine` per criterion and show it. | M | Backend + Frontend | The review screen states which criteria were semantically judged. No single global mode claim. |
| **P0-4** | **Short spans can never ground** — `spanIsGrounded` returns `false` for any span under 12 characters (`:166`). Sensible as a guard against trivial matches, but a legitimately short quote is silently unciteable. Confirm the threshold is deliberate and document it, or lower it and rely on the substring check. | S | Backend | Threshold is either justified in a comment with a test, or changed. |

> **Withdrawn claim.** An earlier draft listed "partial fabrication passes" as a defect, on the
> reading that `:217` only rejects a pass when *zero* spans ground. Reading the code properly:
> `:193` already discards each ungrounded supporting verdict individually, falling back to the
> deterministic criterion for that row. The `claimedSupport > 0 && grounded === 0` check at
> `:217` is an **additional** whole-pass rejection layered on top, not the only one.
> **Per-verdict rejection already works.** No task needed; preserve the behaviour.
