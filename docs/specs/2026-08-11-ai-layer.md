# Talk-Active — AI Layer Specification

**Date:** 2026-08-11 · **Status:** active · **Parent:** [`2026-08-11-target-architecture.md`](2026-08-11-target-architecture.md) §4

Complete component-level specification. Every model call, every schema, every failure path,
every non-model component that checks a model.

---

## 0. The five principles

Every decision below follows from these. If a future change contradicts one, the principle
is what has to be argued with.

| # | Principle | Consequence |
|---|---|---|
| **P1** | **Check model output with something that isn't a model.** | Grounding is a string comparison. Ranking is arithmetic. Progress is SQL. |
| **P2** | **One job, one call, minimum context.** | Never batch criteria. Never pass a criterion into a call not judging it. |
| **P3** | **Never feed model output back into a judging call.** | Verdicts are compared in code. No self-review, no anchoring. |
| **P4** | **Retry only with new information.** | A blind retry is a resample. One retry exists, and a human supplies its input. |
| **P5** | **Degrade, never fail.** | Every unit has a deterministic fallback. The demo cannot break (INV-8). |

**This is a pipeline, not an agent system.** Fixed inputs, schema-constrained outputs, no
tools, no external state, no step whose next action a model chooses. Say "pipeline" in the
pitch — "agent" invites a question whose honest answer is "it's a function call."

## 1. Component map

```
                    ┌── models ──┐   ┌── code, no model ──┐

project setup       RubricParser  →   student confirms
                                       ↓
analyse attempt     EvidenceJudge ×N →  spanIsGrounded()
                    (parallel,          double-count check
                     1 per criterion)   coverage_score
                                        weakest-criterion rank
                                       ↓
challenge           QuestionGenerator → spanIsGrounded(challengedClaim)
                                       ↓
defend              DefenseJudge     →  spanIsGrounded()
                    (= EvidenceJudge)
                                       ↓
progress            —                   SQL aggregation
```

**Three model units. Four non-model checks. One human decision point.**

## 2. Model tiers

Do not pin model IDs in this document — they change. Pin *tiers* and a selection rule.

| Tier | Used by | Selection rule |
|---|---|---|
| **Stronger** | RubricParser, QuestionGenerator | Best instruction-following available in budget. Runs once per project / once per attempt. |
| **Small/fast** | EvidenceJudge, DefenseJudge | Cheapest model that reliably reproduces a span verbatim. Runs N× per attempt. |

**Verbatim reproduction is the selection criterion for the small tier**, not general
benchmark score. A model that paraphrases while quoting is useless here regardless of how
well it reasons, because every paraphrase fails grounding and degrades to deterministic.

Resolve concrete IDs at build time from the live model list; record the chosen IDs in
`.env.example` with the date they were verified.

## 3. `RubricParser`

**Job:** turn a pasted scoring matrix into discrete criteria. Runs once per project.

```ts
// input
{ rubricText: string }                    // ≤ 8,000 chars, raw paste

// output
{ criteria: Array<{
    name: string                          // ≤ 80 chars
    description: string                   // what the evaluator is looking for
    requiredEvidence: string[]            // 1–4 concrete things that would satisfy it
    weight: number | null                 // null when the source states none
  }> }                                    // 1–20 items
```

**Context:** the rubric text only. Never a transcript — it has no business seeing one.

**Validation in code:**
- 1–20 criteria, or the parse is rejected.
- `weight` is `null` unless a number appears in the source. **Never invent weights.**
- Every `name` must be traceable to the input: reject any criterion whose name shares no
  content word with the source text. Catches wholesale invention.

**Failure:** retry once with a stricter prompt. Second failure → the manual rubric editor,
prefilled with the raw text. **Rubric import failing must never block starting a project.**

**Nothing is persisted until the student confirms.** The system never silently guesses what
an evaluator meant. This is a product commitment, not a UX preference.

## 4. `EvidenceJudge`

**Job:** decide whether **one** criterion is supported by the transcript, and cite the span
that proves it. This is the core of the product.

```ts
// input — ONE criterion, never a list
{ transcript: string
  criterion: { name, description, requiredEvidence } }

// output
{ verdict: 'supported' | 'partial' | 'unsupported'
  span: string | null                     // VERBATIM from transcript; null iff unsupported
  missing: string[] }                     // what would have satisfied it; required unless supported
```

**Runs once per criterion, in parallel, via `Promise.allSettled`.**

### Context construction — the caching layout

```
┌─ cached prefix ──────────────────────┐  identical across all N calls
│  system instructions                 │
│  the transcript                      │  ~1,200 tokens
└──────────────────────────────────────┘
┌─ varying suffix ─────────────────────┐
│  this one criterion                  │  ~40 tokens
└──────────────────────────────────────┘
```

Cache writes cost 1.25× base input, reads 0.10× — a 90% discount — on a 5-minute TTL. The
write premium is repaid after one hit.

**Fire call 1, await it, then fan out the remaining N−1.** Fully parallel calls all miss the
cache because none has written it yet. One extra round trip converts the rest to hits.

### Validation in code

1. **`spanIsGrounded(span, transcript)`** — §8.1. Ungrounded → retry once with a stricter
   prompt → on second failure, this criterion falls back to the deterministic analyzer and
   is recorded `engine: 'deterministic'`.
2. **`verdict: 'supported'` with `span: null` is invalid.** Coerce to `unsupported`.
3. **`missing` must be non-empty** unless `supported`. An unsupported verdict that can't say
   what's missing is useless to the student.

### Why one criterion per call

Batching buys position bias — documented as severe, and it coexists with high test-retest
reliability, so a batched judge can be perfectly self-consistent and systematically wrong.
Isolation also makes per-criterion provenance free: which criteria were semantically judged
is a property of the results array, not a claim the UI has to make.

### The cost of isolation, paid in code

Isolated calls cannot see each other, so **the same span may be cited for several criteria**,
inflating apparent coverage. Caught by the double-count check (§8.2), not by context.

## 5. `DefenseJudge` — EvidenceJudge, reused

Same unit, same schema, different input. Judges the student's spoken defense against the one
criterion the question targeted.

```ts
{ transcript: studentAnswer,              // the ANSWER, not the original pitch
  criterion: theTargetedCriterion }
```

**It must not see the original transcript.** It is judging what they just said under
pressure. Including the pitch would let a claim from the original transcript ground a verdict
about the defense — a silent correctness bug, and a violation of P2.

Stored as `evidence_verdicts` with `stage: 'defense'`. No parallel table.

## 6. `QuestionGenerator`

**Job:** write the single adversarial question a skeptical evaluator would ask about the
weakest claim. This is the differentiator — the thing no delivery coach does.

```ts
// input
{ criterion: theWeakestCriterion          // chosen deterministically, §8.3
  missing: string[]                       // from its verdict
  transcript: string }

// output
{ question: string                        // ≤ 200 chars, ONE question
  challengedClaim: string }               // VERBATIM span from transcript
```

### `challengedClaim` is the whole design

**Apply INV-3 to the question, not only to the verdict.** The generator must quote the claim
it is attacking, and that quote runs through **the same `spanIsGrounded` check** already
protecting verdicts.

> *"You said: 'our model reduces prep time by half.' What measurement produced that number?"*

This one constraint kills three failure modes structurally, with no extra call:

| Failure | Why it becomes impossible |
|---|---|
| **Generic slop** — "can you elaborate?" | Cannot be produced; it must quote something real |
| **About nothing** — attacks a claim never made | The quote must exist in the transcript |
| **Unverifiable** | Verified by code you already wrote and tested |

Generic questions are how this feature dies. Any delivery coach can ask "tell me more."

**Validation:** `challengedClaim` ungrounded → regenerate once → on second failure, fall back
to the deterministic `makeJudgeQuestion(criterion)`. The student always gets a question.

**Exactly one question.** A real judge asks one hard thing and watches you handle it. The
product's discipline is "retry one focused section"; a list dilutes it.

## 7. Progress — no model

`AVG(coverage_score) GROUP BY criterion_id ORDER BY created_at`. Most recurring gap is
`MIN(avg)`. Zero model calls, ever.

Worth saying in Q&A: *"the progress view is SQL over stored verdicts"* is a stronger answer
than anything involving a model, because it cannot drift, cost, or hallucinate.

## 8. Non-model components

### 8.1 `spanIsGrounded(span, transcript) → boolean`

**The single most important function in the codebase.** A cited span must appear verbatim in
the transcript or the verdict is discarded in code — not discouraged in a prompt.

It beats any model at this job because it has access to ground truth *outside the model's own
reasoning*. It cannot hallucinate.

**Must normalise before comparing**, or it produces false negatives that silently discard
*correct* verdicts. Current implementation (`src/semantic.mjs:165-169`) does only
`.trim().toLowerCase()` then `includes()`. Add:

- collapse all whitespace runs — a quote spanning a line break is still the same quote
- curly quotes → straight, en/em dash → hyphen
- strip zero-width characters
- **keep the existing case-insensitivity.** Case differences are a transcription artefact, not
  evidence of paraphrase; matching case-sensitively would only manufacture false negatives.

**Map back to original offsets for display**, so the UI highlights the real text.

**Minimum span length.** The current guard rejects spans under 12 characters. This is a
reasonable defence against a trivially-matching fragment, but it makes a legitimately short
quote unciteable. Keep it, document the reasoning in a comment, and cover it with a test —
an undocumented magic number in the most important function in the codebase is a liability.

**Per-verdict rejection, already correct — preserve it.** `:193` discards each ungrounded
supporting verdict individually, dropping that row back to the deterministic criterion. The
whole-pass rejection at `:217` (`claimedSupport > 0 && grounded === 0`) sits on top as a
second layer that catches wholesale fabrication. Both layers are load-bearing; do not collapse
them into one during the port.

### 8.2 Double-count check

Flags any span cited for more than one criterion. Deterministic, no model. Shown on the
review screen — one sentence doing the work of three criteria is exactly what a student needs
to see, and exactly what an evaluator will notice.

### 8.3 Weakest-criterion ranking

Arithmetic, not a model. `coverage_score`: `unsupported` 0, `partial` 0.5, `supported` 1.
Lowest score wins; ties break toward the earliest `display_order`.

**Uncertainty raises scrutiny, never lowers it.** Any criterion flagged — double-counted,
student-rejected, or degraded to deterministic — is ranked as `0.5` for *selection purposes*
regardless of its stored verdict. The system re-examines what it is least sure of.

### 8.4 Deterministic analyzer

Always runs first, supplies the response shape and delivery metrics, and is the fallback for
every unit. `mode`/`engine` is recorded **per criterion**, never as one global claim — a
result badged `semantic` while some criteria were cue-matched is an INV-2 problem hiding in a
UI label.

## 9. Verification and the human loop

Two layers, neither a model.

### 9.1 `spanIsGrounded` — catches fabrication

Absolute. A quote that isn't in the transcript never reaches a user.

### 9.2 The student — decides sufficiency

The review screen asks, per verdict:

> **"Would an evaluator accept this as covering *Business Strategy*?"**
> *"our model reduces prep time by half"* → **Yes** / **No**

**Ask about sufficiency, not intent.** *"Did you mean it that way?"* asks what the student is
already certain of. *"Would an evaluator accept this?"* asks the question they are rehearsing
to answer — and pointing them at it is itself the product's value.

**Honest limit, recorded so nobody forgets it:** the student is authoritative on what they
*meant*, and unreliable on whether it *suffices* — that unreliability is why the product
exists. This layer reliably catches a span about the wrong topic. It only partly catches a
span that is on-topic but too weak. That residual is real and currently unmeasured.

**Design against lazy-clicking**, or the layer is theatre:
- No default selection. Nothing is pre-confirmed.
- Enter/Return does not confirm.
- The span is the visually dominant element, so reading it is the path of least resistance.

### 9.3 On `No` — the one retry in the pipeline

```
student rejects
  → student_overridden = true, rejected span recorded
  → ONE re-judge call, this criterion only:

      "Criterion: X. The student confirms this span does NOT satisfy it:
       '⟨span⟩'. Find different supporting evidence in the transcript,
       or return unsupported."

  → no better evidence → settles at unsupported → feeds weakest-criterion ranking
```

This is the only retry that isn't a resample (P4). The human supplied information the model
did not have, and the search space is strictly smaller than the original call's.

### 9.4 On `Yes`

Record, lock `coverage_score` at 1.0, mark human-confirmed. **No model call.**

### 9.5 Confirmations are an evaluation set, never training data

Every Yes/No is a free human label on a model verdict. Store it with the verdict it judged.

**No fine-tuning.** Three reasons, the second decisive:

1. **Scale.** Beating a good prompt needs thousands of labels. You'd have dozens.
2. **It breaks hard deletion.** Training on student transcripts puts unpublished academic
   work into weights that cannot be unlearned, making the UU PDP No. 27/2022 commitment
   unfulfillable in principle.
3. **You already retired the claim.** The "accumulated rubric archetype library" moat was
   dropped for lack of data. Building a training pipeline re-opens it.

The labels answer what no amount of architecture argument can: **how often is the judge wrong,
and in which direction?**

### 9.6 No LLM verifier — and what would change that

A model verifier would check work a human checks ten seconds later. The student reviews all
4–6 verdicts; that screen *is* the product. **Verification belongs where nobody looks.**

The literature also closes the cheap substitute: self-consistency measures determinism, not
correctness, and standing guidance is never to use the same model family as generator and
judge — which is exactly the shape a self-verifier would take.

**Add one when any of these is true:**
- ~20+ criteria, where flagging becomes *triage* rather than verification
- Unsupervised runs — Campus tier, lecturer sees aggregates, nobody inspects verdicts
- Collected labels show an on-topic-but-insufficient rate high enough to matter

**When that day comes, prefer an NLI entailment model** (DeBERTa / multilingual XLM-RoBERTa
class) over a generative call: span-supports-criterion *is* an entailment task, and NLI runs
at a fraction of the cost and latency.

**But NLI is not a drop-in, and the objections are recorded here so they aren't rediscovered:**
abstract rubric criteria are off-distribution for sentence-pair NLI; multilingual NLI is
weaker on Indonesian and code-mixed input; a threshold is a tuning surface; and it returns a
score with no citation to explain it. Validate against real labels before trusting it.

`verifier_agreed` and `verifier_note` stay in the schema so adding this is purely additive.

## 10. Provider strategy

**Hand-rolled failover chain. Keep it even after adopting an SDK.**

A gateway fails over on provider *unavailability*. It will not retry an HTTP 200 containing a
fabricated quote — and **"well-formed response, invented citation" is this product's most
valuable failover trigger.** Grounding-failure-triggered retry is application logic and stays
application logic. An SDK replaces the transport, not the judgment.

**Availability comes from provider diversity, not model diversity.** Three models from one
vendor share one outage.

```
grounding fails on vendor A  → retry stricter on vendor A
still fails                  → vendor B
still fails                  → deterministic, engine: 'deterministic'
total budget exceeded        → deterministic, immediately
```

**Client timeout must exceed the server chain budget.** A chain that legitimately succeeds
inside its budget but outside the client's is discarded, and the demo silently shows
deterministic mode. Assert this relationship in a test — it is not obvious from either file.

## 11. Failure matrix

| Failure | Handling |
|---|---|
| Schema validation fails | Retry once, stricter. Then that criterion → deterministic, labelled. |
| Span not verbatim | Retry once. Then verdict → `unsupported`, `citation_failed: true`. Never fabricated as supported. |
| One criterion fails, others succeed | `Promise.allSettled`. Map still renders; failed criterion gets inline retry. |
| `challengedClaim` ungrounded | Regenerate once → deterministic `makeJudgeQuestion`. |
| RubricParser fails | Manual editor prefilled with raw text. Never blocks project creation. |
| Provider outage | Next vendor in chain, then deterministic. |
| Total budget exceeded | Deterministic immediately. Never hang. |
| Rate limit hit | 429 with a plain message. Never a silent hang. |
| Transcript over cap | Reject loudly with the limit stated. **Never silently truncate** (INV-7). |

**No failure produces a wrong answer presented as a right one.** Every degradation is
labelled on screen at the criterion that degraded.

## 12. Cost

Five criteria, ~900-word transcript, small/fast tier:

| | Uncached | Cached |
|---|---:|---:|
| EvidenceJudge ×5 | ~6,200 in | ~1,700 effective |
| QuestionGenerator | ~1,300 in | ~1,300 |
| DefenseJudge | ~400 in | ~400 |
| **Per session** | **~$0.012** | **~$0.006** |

≈ **Rp 100/session** against the proposal's Rp 1,500 (`body.tex:404-408`) — conservative by
roughly 15×, which strengthens the margin argument rather than weakening it.

**7 model calls per session.** 5 judge + 1 question + 1 defense. Latency is **2 round trips**
regardless of criterion count, since each stage fans out in parallel.

Response cache keyed by `hash(transcript + rubric + durationSeconds)` makes a repeated stage
demo instant. **Never cache a degraded result** — one blip would otherwise pin the whole
session to deterministic mode.

## 13. Prompt and output rules

### 13.1 Use constrained decoding, not schema-in-the-prompt

Schema adherence is a solved problem at the syntactic level and should not be left to
prompt politeness. Reliability by method:

| Method | Schema adherence |
|---|---|
| Native JSON mode / grammar-constrained decoding | ~99.9% |
| Tool / function calling | ~99% |
| Schema described in the prompt | 95–98% |

Anthropic shipped constrained decoding in November 2025. **Use the native structured-output
path of whichever provider is in the chain**, and keep schema-in-prompt only as the fallback
for a provider that lacks it. That converts a 2–5% malformed-response rate — every one of
which currently costs a retry or a degradation — into a rounding error.

**This does not weaken any code-side validation.** Constrained decoding guarantees the
*shape*, never the *truth*. `spanIsGrounded` still rejects a perfectly-formed fabricated
quote, and that is the check that matters.

### 13.2 Give the model room to think before formatting

Structured generation does not degrade quality when the prompt leaves space to solve the task
before formatting it; reported "format tax" is usually a prompt that forced formatting too
early. Put a short free-text `reasoning` field **before** the verdict fields in the schema so
generation order gives the model somewhere to work, and drop it before persisting.

### 13.3 Every prompt, without exception

1. **Names the exact criterion** it is judging. Never "the criteria."
2. **Forbids inventing quotes**, and states that a non-verbatim span will be discarded.
3. **Requires `missing[]`** on any non-supported verdict.
4. **Emits no numeric confidence, ability, or talent score.** Not a UI decision — the model
   must not produce one.
5. **Never sees another model's output.**

Prompts live in a versioned file, one per unit. A prompt change is a code change and goes
through the gate.

## 14. Observability

Log per analysis — no transcript content:

- grounding failure rate per unit and per vendor — **the leading indicator of quality decay**
- cache hit rate
- per-criterion `engine`
- vendor used, retries, latency per stage
- student agreement rate — **the only external measure of correctness you will have**

A rising grounding-failure rate on one vendor is the signal to reorder the chain.

## 15. Deliberately absent

| Not built | Why |
|---|---|
| Retrieval / candidate-span selection | A 900-word transcript fits whole. Retrieval adds a tuning surface and a silent-failure mode for no gain. Earns its place at 20-minute transcripts. `body.tex:232` should be amended to match. |
| LLM verifier | §9.6. Checks work a human checks seconds later. |
| Cross-provider blind re-judge | Full-context re-run inherits pass 1's failure modes; comparison is ill-defined when spans differ; costs ~20× a targeted check. |
| Agentic loops | No tools, no external state, no model-chosen next action. |
| Fine-tuning | §9.5. Breaks hard deletion. |
| Numeric confidence or ability scores | Product commitment. A model saying "73% confident" is a plausible guess, not a calibrated probability. |
| Claim segmentation | Deferred, not rejected — "what did you say that earned nothing?" is a genuinely differentiated feature. Post-hackathon. |

## 16. Open, and honest about it

1. **The on-topic-but-insufficient error rate is unmeasured.** Every verification argument in
   this document is mechanism reasoning with zero measurements from real data. §9.5 labels
   are the instrument; ship them before choosing anything downstream of them.
2. **Indonesian/code-mixed verbatim reproduction is unverified.** Whether the small tier
   quotes ID/EN speech verbatim is an empirical question. Test early — it determines the
   model choice, and a paraphrasing model makes the whole layer degrade to deterministic.
3. **Free-tier reachability.** `src/semantic.mjs:50-53` records the gateway free tier
   rate-limiting every model on 10 Aug. Confirm the credit balance before depending on it.

## 17. Evidence base

Which decisions rest on published findings, and which are ours. Stated so a reviewer can
separate the two — and so that when one of these is superseded, the decision it supports gets
revisited rather than inherited.

| Decision | Rests on | Source |
|---|---|---|
| **No self-review verifier** (§9.6) | Intrinsic self-correction — a model revising its own output with no external signal — fails to improve reasoning and **can degrade it**. A verifier reading its own family's verdict is that pattern. | [Huang et al., *LLMs Cannot Self-Correct Reasoning Yet*](https://arxiv.org/abs/2310.01798) |
| **The one retry is on student rejection** (P4, §9.3) | Same paper's converse: external feedback, when genuinely available, **is** worth acting on. A student rejection is external ground truth; a blind retry is not. | [Huang et al.](https://arxiv.org/abs/2310.01798) · [Automatically Correcting LLMs (TACL)](https://direct.mit.edu/tacl/article/doi/10.1162/tacl_a_00660/120911/) |
| **One criterion per call, never batched** (§4) | Position bias in LLM judging is severe and **coexists with high test-retest reliability** — a batched judge can be perfectly self-consistent and systematically wrong. | [Reliability without Validity](https://arxiv.org/pdf/2606.19544) · [Judging the Judges](https://arxiv.org/pdf/2604.23178) |
| **Self-consistency rejected as a confidence signal** (§9.6) | Same finding: running a model twice measures determinism, not correctness. | [Reliability without Validity](https://arxiv.org/pdf/2606.19544) |
| **Pass 2 on a different vendor, if ever built** (§9.6) | Standing guidance: never use the same model family as generator and judge. | [DeepEval, *LLM-as-a-Judge 2026*](https://deepeval.com/blog/llm-as-a-judge) |
| **Student labels as an eval set** (§9.5) | Judge validation must be calibrated against human labels; mechanism argument alone does not establish validity. | [Judging the Judges](https://arxiv.org/pdf/2604.23178) |
| **Transcript in a cached prefix** (§4) | Writes 1.25× base input, reads 0.10×, 5-minute default TTL; premium repaid after one hit. | [PromptHub](https://www.prompthub.us/blog/prompt-caching-with-openai-anthropic-and-google-models) · [Cache-First Agent Design](https://www.digitalapplied.com/blog/prompt-caching-economics-cache-first-agent-architecture-2026) |
| **Pipeline, not agents** (§0) | Workflows orchestrate models through predefined code paths; agents let models direct their own process. Classification-shaped problems are pipelines, and simple composable patterns beat frameworks. | [Agentic Design Patterns 2026](https://www.sitepoint.com/the-definitive-guide-to-agentic-design-patterns-in-2026/) |
| **Constrained decoding over schema-in-prompt** (§13.1) | ~99.9% adherence vs 95–98%; Anthropic shipped constrained decoding Nov 2025. | [JSONSchemaBench](https://arxiv.org/pdf/2501.10868) · [Structured Outputs & Constrained Decoding](https://www.tmls.nyc/research/structured-outputs-constrained-decoding) |
| **Reasoning field before verdict fields** (§13.2) | Structured generation matches unstructured quality when the prompt leaves room to solve before formatting. | [Structured Output Reliability in Small LMs](https://arxiv.org/pdf/2605.02363) |
| **NLI as the eventual verifier, not a generative call** (§9.6) | Claim verification is a recognising-textual-entailment task; entailment models are purpose-built and far cheaper than LLM judging. | [Automated Fact-Checking: A Survey](https://arxiv.org/pdf/2109.11427) · [Tuning LLM Judge Design for 1/1000 of the Cost](https://arxiv.org/pdf/2501.17178) |

### Where the literature does *not* transfer

Most LLM-as-judge work evaluates **preference and quality** judging — which of two responses
is better. Talk-Active does **grounded attribution against a fixed rubric**: a bounded
classification with a verbatim-citation requirement.

Position bias, model-family independence, and human calibration transfer cleanly. **Pairwise
comparison with both orderings does not** — there is no pair to order — so it is not adopted
here despite being standard advice.

### Decisions that rest on no published finding

Ours, from this product's constraints, and the first to revisit if they prove wrong:

- **Student confirmation as the sufficiency check** (§9.2). Follows from "verification belongs
  where nobody looks" plus the fact that the review screen is the product. Untested.
- **`challengedClaim` must ground** (§6). An application of INV-3 to questions. Not a
  published pattern.
- **Retrieval omitted** (§15). A judgement about transcript length, not a finding.
- **The on-topic-but-insufficient error rate** (§16.1). Unmeasured. Everything downstream of
  it is mechanism reasoning until §9.5 labels exist.
