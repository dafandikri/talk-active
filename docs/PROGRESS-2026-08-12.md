## 3. Windows was breaking the gate silently — read this if you use Windows

Two separate defects, both pre-existing, neither in any plan.

**`scripts/serve.mjs`** normalised URL paths with the platform's rules. On Windows
`/src/app.mjs` became `src\app.mjs`, missed the `startsWith('src/')` allow-list, and 404'd.
**Every stylesheet, module, and asset. `pnpm dev` served bare, inert HTML.** The repository's own
`test/server.test.mjs` had been failing there all along.

**`findBrowser()`** searched macOS application paths and the POSIX Playwright cache only. On
Windows it found nothing, so both browser gates reported `status: skipped` and **exited 0**. The
merge permission was being granted by a gate that never ran. CI already guards this by failing
on `status: skipped`; a laptop had no such guard.

Both are fixed. Backslashes are now folded to slashes *before* normalising, never after — a
percent-encoded `%5C` would otherwise reach the allow-list as a clean `src/../../secret` that
escapes the root. That ordering is asserted in a test, not just described in a comment.

**If you are on Windows:** pull `main`, then re-run `node scripts/browser-check.mjs` and
`node scripts/demo-gate.mjs`. They will actually execute now.

## 4. Two bugs inside `finals-hardening.md` — before anyone starts the backend track

The plan is written to be executed literally, task by task. Two tasks cannot be.

**Task 6 double-parses the gateway response.** `callGateway` in `src/semantic.mjs` already
returns `extractJson(text)` — a parsed object. The plan then calls `extractJsonPayload(text)` on
top of it, which stringifies the object to `"[object Object]"` and throws. Every vendor fails,
and the plan's own test `import returns rubric lines when the model answers` can never pass.
Drop the second parse.

**Task 2 Step 5 writes a test that throws instead of returning.** It passes one criterion with a
span that fails grounding, so `claimedSupport > 0 && grounded === 0` fires at `src/semantic.mjs:217`
and `applySemanticVerdicts` throws before the assertion runs. The test needs two criteria — one
grounded, one not — so the whole-pass guard does not trigger.

Minor: the zero-width-character class in Task 2's `normaliseForGrounding` is written with literal
invisible characters. Write it as the escaped range `​` to `‍` plus `﻿` instead, so
it survives copy-paste — a character class you cannot see is one you cannot review.

## 5. Decisions the team needs to make

### 5.1 Test 77 — needs agreement, not an individual call

`local push and remote CI both enforce the same complete gate` reads the executable bit off the
filesystem. Windows cannot represent it — `chmod +x` was tried and is a no-op, mode stays `666`.
Git already records `.githooks/pre-push` as `100755`, so the property holds correctly on Linux,
macOS, and CI. **Only the test's choice of source is wrong on one platform.**

The only fix is to change a test, and `AGENTS.md` requires *"the team's agreement"* for that.

A defensible option, if the team agrees: read the mode from git's index (`git ls-files -s` must
report `100755`) rather than from the filesystem. That is arguably *stronger*, because what
determines whether the hook is executable on someone else's machine is the mode git distributes,
not the mode one filesystem can express. On Linux and macOS both agree.

**Until this is decided, do not run `pnpm setup:hooks` on Windows** — the hook runs `pnpm check`
and will block every push.

### 5.2 The stack claim in the proposal is unowned

`body.tex` Table 3 promises Next.js, Postgres, and Clerk. The build that ships is vanilla JS on
`localStorage`. `target-architecture.md` names this as an INV-2 gap and chose to close it by
migrating — and the migration is now post-hackathon.

PP-1..PP-9 correct the competitor and market claims. **None of them touch the stack claim.** A
judge who read the proposal will ask to see Postgres. The same discipline we applied to Yoodli
(name it before they do) has not been applied to our own architecture.

### 5.3 The offline laptop cannot run semantic mode

`apiIsReachable()` in `src/app.mjs` returns `false` for `localhost` and `127.0.0.1`. The offline
demo laptop is therefore **always deterministic**.

The risk register in `2026-08-10-innovation-week.md` lists the wifi-drop mitigation as *"run from
localhost on the demo laptop"*. Those two facts cancel: the thing that saves us from dead wifi is
the thing that disables the hero moment. Someone should decide which one we are betting on before
Friday, rather than discovering it on stage.

### 5.4 `ai-layer.md` describes a system that will not be on stage

The spec forbids batching criteria, with a documented reason (position bias). What ships,
`src/semantic.mjs:99-135`, sends **all criteria in one batched call**. The per-criterion design
lives in the migration track.

That is a reasonable decision. But it means **any deck slide or Q&A answer describing the AI
layer from that document is an INV-2 violation.** We need one agreed sentence separating "what
runs today" from "the target architecture".

### 5.5 The active spec still carries retired numbers

`2026-08-10-innovation-week.md` §9 still reads *"81% report speaking anxiety; the LPDP interview
passes 6.7%"* — both retired by `2026-08-12-positioning.md` (PP-3, PP-4). Anyone writing the deck
from the sprint spec alone will write claims we already know are wrong.

### 5.6 This work has no backlog ID

The Windows fixes are not B-anything or F-anything. If nobody records them, the work is invisible
and the next person rediscovers the bugs.

`origin/main` has since moved to `955cffb` — two commits re-cutting the backlog, touching only
`docs/specs/2026-08-11-backlog.md`. **No collision with any code changed here.**

The team's convention is a direct push to `main`, not pull requests: both remote commits landed
linearly with no merge commit, which matches `AGENTS.md` — *"Nobody needs permission to merge;
green `pnpm check` is the permission."*

```bash
git status --short            # must be empty
git fetch origin
git checkout main
git merge origin/main         # clean: different files
node scripts/browser-check.mjs   # expect 17/17
node scripts/demo-gate.mjs       # expect 10/10, console[0]
node --test                      # expect 130/131, only `not ok 77`
git push origin main
git push origin fix-windows-static-paths b3-kiosk-reset b4-empty-states b5-mobile-390
```

The last line is optional — those commits are already in `main`. It exists so each unit stays
readable on its own and so the branch names match `HANDOVER.md`.

**CI will be green even though the local gate is red.** On ubuntu, git checks the hook out with
the `100755` mode it records, so test 77 passes there. Check the Actions tab to confirm rather
than assuming.

If `git push` is rejected as non-fast-forward, someone pushed in between. **Do not force.** Repeat
the fetch, merge, and gate steps, then push again.
